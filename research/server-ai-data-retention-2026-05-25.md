# Civic Copilot Server and AI Data Retention Research

작성일: 2026-05-25
연결 반복: Cycle 14 - 서버/AI 데이터 보관 설계

## 목적

Cycle 13에서 최근 분석 이력의 로컬 저장을 최소화했다. 이번 재조사는 실제 AI 연동 단계로 확장할 때 서버와 AI 로그가 어떤 데이터를 보관하지 않아야 하는지 정리하기 위한 것이다.

## 공식 근거

| 자료 | 확인한 사실 | 설계 반영 |
|---|---|---|
| 개인정보보호위원회 AI 개인정보보호 자율점검표 | AI 서비스 기획·설계 단계부터 Privacy by Design을 적용하고, 수집, 이용·제공, 보관·관리, 파기, 투명한 공개, 권리행사 절차를 점검하도록 안내한다. | 데이터 보관 정책은 나중에 붙이는 고지가 아니라 시스템 설계 산출물에 포함한다. |
| 개인정보보호위원회 개인정보 처리방침 파기 절차 | 보유기간 경과, 처리목적 달성 등 개인정보가 불필요하게 되었을 때 지체 없이 파기하고, 전자 파일은 재생할 수 없도록 파기하는 원칙을 안내한다. | 원본 사진, 상세 위치, 신고문 원문은 분석 목적이 끝나면 삭제 대상으로 둔다. |
| 개인정보보호위원회 생성형 AI 개인정보 처리 안내 공개 | 생성형 AI 서비스를 개발·활용하는 기업·기관을 위한 개인정보 안전 처리 기준이 공개되었다. | 향후 VLM/LLM/RAG 연동은 원본 데이터 전송, 로그 저장, 모델 개선 데이터 사용을 별도 통제해야 한다. |
| 개인정보보호위원회 공개된 개인정보 처리 안내서 | AI 개발·서비스에서도 목적과 필요성, 안전조치, 권리보장 검토가 필요하다. | "서비스 개선"이라는 이유로 신고 원문이나 사진 원본을 장기 보관하지 않는다. |

## 설계 결론

MVP와 실제 서비스 확장 단계의 데이터 보관 원칙을 분리한다.

| 단계 | 보관 원칙 |
|---|---|
| MVP 데모 | 서버 DB 없음. 입력은 메모리에서 분석 후 응답으로만 반환. 사진 원본은 브라우저 미리보기에서만 사용. API에는 사진 첨부 여부만 전송. |
| AI 연동 실험 | VLM/LLM 요청에는 필요한 최소 이미지와 텍스트만 보내고, 원본 사진은 짧은 TTL 후 삭제. |
| 제품화 | 상세 위치, 신고문 원문, 사진 원본은 기본 장기 저장 대상에서 제외. 사용자 동의가 있는 품질 개선도 비식별 메타데이터 중심. |
| 공식 제출 | 안전신문고, 서울 스마트 불편신고, 국민신문고 같은 공식 채널에서 제출과 처리결과를 관리. Civic Copilot 저장소와 분리. |

## MVP 반영

1. 브라우저는 선택한 파일명을 화면에 보여줄 수 있지만, API 요청에는 `photoName`을 보내지 않는다.
2. 서버는 클라이언트가 `photoName`을 보내더라도 normalize 단계에서 버린다.
3. analyzer 결과에 `dataLifecyclePolicy`를 추가해 서버 무저장, 사진 원본 브라우저 한정, 향후 AI 로그 비식별화, 삭제/권리 대응을 설명한다.
4. 결과 화면에 `서버/AI 데이터 보관 설계` 섹션을 추가한다.

## 다음 확장 과제

- 실제 이미지 업로드가 들어갈 경우 파일 저장소 TTL과 삭제 작업 설계
- 서버 로그에서 위치, 신고문, 파일명, IP 등 식별 가능 데이터 제거
- 모델 개선 데이터셋 생성 시 가명처리/비식별 처리 절차
- 사용자 동의 철회와 삭제 요청 경로
