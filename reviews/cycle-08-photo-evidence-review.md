# Cycle 08 - Photo Evidence Completeness Review

## 검토 질문

사진 입력이 실제 공식 신고 준비 요건으로 다뤄지고 있는가, 아니면 데모 화면의 장식으로만 남아 있는가?

## 재조사 근거

- 행정안전부 안전신문고 업무안내는 안전위험요인을 보면 사진이나 동영상을 촬영한 후 간단한 신고내용과 지도상 위치를 지정해 제출한다고 안내한다.
- 같은 안내에서 신고 진행상황과 처리결과는 안전신문고 홈페이지 또는 앱에서 확인할 수 있다고 설명한다.
- 따라서 Civic Copilot은 사진을 장기 저장하거나 공식 처리 결과를 대신 관리하지 않고, 제출 전 사진 증거 부족을 사용자에게 알려주는 보조 역할에 머물러야 한다.

## 발견한 설계 공백

기존 MVP는 사진 선택 UI와 샘플 이미지 미리보기는 있었지만, 분석 요청에는 사진 선택 여부가 전달되지 않았다. 이 상태에서는 사용자가 실제 사진을 선택하지 않아도 `사진 분석` 단계가 있는 것처럼 보이고, 일부 증거 체크가 충족된 것처럼 표시될 수 있었다.

이 공백은 AD 프로젝트 기준에서 중요하다. 구현 자체보다 설계 논리가 핵심인데, 사진이 공식 신고의 핵심 입력이라면 데모도 사진 유무를 별도 상태로 다뤄야 한다.

## 페르소나 리뷰

| 관점 | 우려 | 설계 반영 |
|---|---|---|
| 대학생 시민 | 샘플 이미지가 있어서 사진을 넣은 줄 착각할 수 있음 | 실제 파일 선택 여부를 분석 입력으로 전달 |
| 행정 담당자 | 사진 없는 신고는 현장 확인과 판단이 어려움 | `사진 증거 완성도`에서 보완 필요 표시 |
| 디지털 취약 사용자 | "사진을 더 찍으라"는 말만으로는 무엇을 찍을지 모름 | 현장 사진, 전체 배경 사진, 근접 사진으로 나눠 안내 |
| 안전/윤리 검토자 | 긴급 상황에서 촬영을 강요하면 위험 | 긴급 상황은 사진보다 112/119 직접 신고 우선 |

## 구현 반영

- 분석 입력에 `hasPhoto`, `photoName`을 추가한다.
- 사진이 없으면 `photoEvidenceAssessment.status = "missing"`으로 반환한다.
- 사진이 없으면 증거 체크리스트에 `현장 사진 첨부` 필수 항목을 추가한다.
- 공식 제출 전 확인 목록에 `사진 첨부` 단계를 추가한다.
- UI 결과 화면에 `사진 증거 완성도` 섹션을 추가한다.

## 테스트 기준

- 사진이 없을 때 분석 엔진은 `cycle-08` 사진 증거 완성도 결과를 반환해야 한다.
- 모바일 UI는 `사진 증거 완성도`, `현장 사진 추가`, `전체 배경 사진`, `근접 사진`을 표시해야 한다.
- 공식 제출 전 확인에는 `사진 첨부`가 포함되어야 한다.

## 결론

Cycle 08의 결론은 단순하다. Civic Copilot은 사진을 대신 제출하거나 보관하는 시스템이 아니라, 공식 제출 전에 사진 증거가 빠졌는지 알려주는 신고 준비 코치여야 한다. 이 범위가 AD 프로젝트의 설계 목표와 공식 플랫폼과의 책임 경계를 모두 만족한다.
