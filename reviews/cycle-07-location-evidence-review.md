# Cycle 07 Location Evidence Review

## 검토 배경

보고서의 테스트 케이스에는 `위치 없음` 상황이 있었지만, 기존 MVP는 위치가 비어도 `현장 위치`로 대체해 신고문을 만들었다. 이는 실제 신고 품질을 숨기는 동작이다. Civic Copilot이 신고 전 검증 도구라면, 위치 누락을 조용히 보정하기보다 공식 제출 전 보완해야 할 상태로 드러내야 한다.

이번 반복의 공식 근거는 두 가지다.

- 행정안전부 안전신문고 업무안내는 안전위험요인을 사진이나 동영상으로 촬영한 후, 간단한 신고내용과 지도상 위치를 지정해 제출한다고 설명한다.
- 국민신문고 민원 이용 안내는 신청서 작성 단계에서 주소, 연락처, 민원제목과 내용 등을 작성한다고 설명한다.

## 페르소나별 리뷰

| 관점 | 우려 | 설계 반영 |
|---|---|---|
| 대학생 시민 | 급하게 신고문만 복사하면 위치를 빼먹을 수 있다. | 위치가 비어 있으면 신고문 첫 문장에 위치 미입력 상태를 명시한다. |
| 디지털 취약 사용자 | "주소를 정확히 쓰라"는 말만으로는 무엇을 입력해야 할지 어렵다. | 지도 위치 지정, 주변 기준점, 사진 배경 보완이라는 행동 단위로 안내한다. |
| 외국인 주민 | 도로명주소를 몰라도 신고할 수 있어야 한다. | 건물명, 정류장, 가로등 번호, 주변 표지처럼 주소 대체 단서를 허용한다. |
| 행정 담당자 | 위치가 없으면 담당 부서 배정과 현장 확인이 어렵다. | 공식 제출 전 확인 체크리스트에 `위치 보완`을 추가한다. |
| 안전/윤리 검토자 | 긴급 상황에서 앱 위치 입력을 강요하면 대응이 늦어진다. | 긴급 상황은 앱 입력보다 112/119에 현재 위치를 직접 알리도록 안내한다. |
| 발표 평가자 | 구현 데모가 설계의 "증거 요건 점검"을 더 명확히 보여줘야 한다. | MVP 결과 화면에 `위치/증거 완성도` 섹션을 추가한다. |

## 구현 반영

- `analyzeIncident()` 결과에 `locationAssessment`를 추가했다.
- 위치가 있으면 `status: ready`, 위치가 없으면 `status: missing`으로 반환한다.
- 위치가 없을 때 신고문은 `위치가 아직 입력되지 않았습니다`로 시작한다.
- 위치가 없을 때 공식 제출 전 확인 체크리스트에 `위치 보완`을 추가한다.
- MVP UI에는 `위치/증거 완성도` 섹션과 `data-location-action` 항목을 추가했다.

## 테스트 반영

- analyzer 테스트: 위치 누락 시 cycle-07, `missing`, `requiredBeforeSubmit`, 지도 위치 지정/주변 기준점/사진 배경 보완 안내를 검증한다.
- UI smoke 테스트: 모바일 화면에서 위치/증거 완성도 섹션, 위치 보완 체크리스트, 위치 미입력 신고문을 검증한다.

## 결론

위치 정보는 신고 편의 기능이 아니라 처리 가능성을 좌우하는 핵심 증거다. AD 프로젝트 관점에서는 이 모듈이 "사진, 위치, 설명의 충분성을 점검한다"는 설계 목표를 실제 데모에서 더 잘 드러낸다.
