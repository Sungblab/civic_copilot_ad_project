# Cycle 06 Feedback Loop Review

## 검토 배경

확정 기획은 Civic Copilot을 공식 신고 플랫폼이 아니라 신고 전 AI 보조 레이어로 둔다. 따라서 피드백 루프도 공식 처리 결과를 대신 수집하거나 평가하는 기능이 아니라, 접수 전 보조 품질을 개선하는 작은 신호로 제한해야 한다.

이번 반복에서는 국민신문고 민원 이용 안내의 처리 절차를 확인했다. 국민신문고는 신청서 작성, 유사사례 검토, 처리기관 선택 및 제출, 접수, 처리, 완료 후 만족도 조사 흐름을 제공한다. 이 구조는 "피드백이 공공 민원 서비스 개선에 필요하다"는 근거가 되지만, Civic Copilot이 위치·신고문 원문·사진 원본까지 개선 로그로 저장해도 된다는 뜻은 아니다.

## 페르소나별 리뷰

| 관점 | 우려 | 설계 반영 |
|---|---|---|
| 대학생 시민 | 신고 후 긴 설문을 요구하면 현장 사용 흐름이 끊긴다. | 신고문 도움됨, 보완 필요, 공식 제출 완료 3개 선택지만 제공한다. |
| 디지털 취약 사용자 | 피드백 의미가 복잡하면 잘못 누르거나 포기할 수 있다. | 버튼 라벨을 짧게 만들고 각 선택지에 한 문장 설명을 붙인다. |
| 외국인 주민 | 한국어 신고문이 실제 제출에 도움이 되었는지 쉽게 표시해야 한다. | "신고문 도움됨"을 문장 생성 품질 신호로 둔다. |
| 행정 담당자 | 피드백이 중복 신고나 공식 처리 상태와 섞이면 책임 경계가 흐려진다. | 공식 제출 완료는 익명 전환 신호로만 보고, 처리번호나 민원 원문은 요구하지 않는다. |
| 개인정보 책임자 | 개선 데이터라는 이유로 위치와 신고문 원문을 저장하면 개인정보 최소수집 원칙이 흔들린다. | `anonymous-choice-only` 모드로 선택값, 시나리오, 추천 유형, 반복 버전만 저장한다. |
| 발표 평가자 | 피드백 루프가 있으면 MVP가 설계 검증 도구라는 주장이 더 설득력 있다. | MVP 결과 화면에 `피드백 루프` 섹션을 추가하고, 리서치-리뷰-수정 반복의 cycle-06으로 기록한다. |

## 구현 반영

- `analyzeIncident()` 결과에 `feedbackLoop`를 추가했다.
- MVP UI에 `피드백 루프` 섹션을 추가했다.
- 선택형 피드백은 브라우저 `localStorage`의 `civic-copilot-feedback`에 최대 10건 저장한다.
- 저장 항목은 `feedbackType`, `label`, `scenario`, `primaryType`, `iteration`, `privacyMode`로 제한했다.
- 위치, 신고문 원문, 사진 원본은 피드백 로그에 저장하지 않는다.

## 테스트 반영

- analyzer 테스트: `feedbackLoop.iteration`, `basis`, `privacyMode`, 선택지, 평가 지표, 개인정보 고지를 검증한다.
- UI smoke 테스트: 피드백 선택 후 1건 저장 표시가 나타나고, 저장 레코드에 `location`과 `draft`가 없는지 검증한다.

## 결론

피드백 루프는 설계 프로젝트의 반복 검증 구조에 부합한다. 단, 장기 제품에서도 공식 민원 처리 상태를 직접 추적하려면 기관 협약, 인증, 감사 로그, 개인정보 영향 검토가 선행되어야 한다. AD 프로젝트 MVP에서는 선택형 비식별 피드백까지만 구현하는 것이 적절하다.
