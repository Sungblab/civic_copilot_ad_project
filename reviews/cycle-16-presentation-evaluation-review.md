# Cycle 16 - Presentation and Evaluation Alignment Review

## 목적

Cycle 15까지 기능과 안전장치 설계가 충분히 촘촘해졌다. 이번 반복은 AD 프로젝트 평가 기준에 맞춰 산출물을 다시 정렬한다. 핵심은 "많이 만들었다"가 아니라 문제 정의, 조사, 설계 논리, 구현 가능성, 발표 전달력을 7분 안에 분명히 보여주는 것이다.

참조 리서치: `research/presentation-evaluation-alignment-2026-05-25.md`

## 과제 기준 매핑

| 평가 축 | 현재 강점 | 보강 방향 |
|---|---|---|
| 문제 정의와 해결 방안의 논리 구조 | 신고 전 판단 부담이라는 좁은 문제로 정리되어 있다. | "플랫폼 부재"가 아니라 "접수 전 준비 실패"로 계속 표현한다. |
| 요소 기술 조사와 파악 | VLM, LLM, RAG, 규칙 DB, 채널 라우터, 개인정보 모듈이 분리되어 있다. | 각 기술을 기능명 나열이 아니라 맡은 역할로 설명한다. |
| 발표 형식과 의사 전달 | HTML 슬라이드와 MVP 데모가 있다. | 7분 발표에서는 데모 세부 기능을 모두 말하지 않고 4개 하이라이트로 압축한다. |
| 구현 가능성 | rule/mock MVP와 실제 확장 구조가 분리되어 있다. | MVP는 설계 검증 도구라고 명시하고, 실제 AI 연동은 향후 구현 가능성으로 둔다. |

## 페르소나 리뷰

| 관점 | 검토 질문 | 결정 |
|---|---|---|
| 동료 평가자 | 한 문장으로 기억되는가 | "기존 서비스는 신고를 받는다. Civic Copilot은 시민이 신고를 잘할 수 있게 만든다."를 초반과 결론에 반복한다. |
| 교수/평가자 | AD 기준의 착안-조사-설계 흐름이 보이는가 | 슬라이드 08을 평가 기준에 맞춘 반복 루프로 바꾼다. |
| 기술 검토자 | 요소기술이 과장되지 않는가 | MVP는 rule/mock, 제품화는 VLM/LLM/RAG/규칙 DB 조합으로 분리한다. |
| 발표자 | 7분 안에 말할 수 있는가 | 대본 본문은 6분 55초 이내로 압축하고, 상세 안전장치는 백업 설명으로 뺀다. |
| 청중 | 기능이 너무 많아 산만하지 않은가 | 데모 설명은 증거, 채널, 신고문, 안전장치 4개만 말한다. |

## 결정

발표의 우선순위는 과제 점수 기준을 따른다. 데모는 플러스 알파이지만, 발표에서는 "구현량"으로 밀지 않는다. 데모는 설계가 실제 사용자 흐름으로 성립한다는 증거로만 사용하고, 핵심 평가는 문제 정의, 공식 자료 조사, AI/SW 설계, 구현 가능성에 맞춘다.
