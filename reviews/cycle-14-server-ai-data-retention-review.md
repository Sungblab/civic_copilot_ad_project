# Cycle 14 - Server and AI Data Retention Review

## 목적

MVP가 rule/mock 기반이어도, 실제 AI 연동을 상상한 설계에서는 서버와 AI 로그의 데이터 보관 정책이 필요하다. 이번 반복은 "사진·위치·신고문을 분석하지만 오래 저장하지 않는 시스템"을 결과 화면과 API 동작에 반영한다.

참조 리서치: `research/server-ai-data-retention-2026-05-25.md`

## 페르소나 리뷰

| 관점 | 검토 질문 | 반영 |
|---|---|---|
| 대학생 시민 | 현장 사진 파일명이 서버에 남지 않는가 | 클라이언트 API 요청에서 `photoName`을 제거했다. |
| 디지털 취약 사용자 | 서버가 무엇을 저장하는지 쉬운 문장으로 알 수 있는가 | 결과 화면에 `서버/AI 데이터 보관 설계` 섹션을 추가했다. |
| 외국인 주민 | 사진과 위치를 넣어도 과도한 저장이 되지 않는가 | 사진 원본은 브라우저 미리보기 한정, API에는 첨부 여부만 전송한다고 설명한다. |
| 행정 담당자 | 공식 접수 데이터와 보조 도구 데이터가 섞이지 않는가 | 공식 제출과 처리결과는 공식 채널에 남기고 Civic Copilot 저장소와 분리한다고 명시한다. |
| 안전/윤리 검토자 | Privacy by Design, 보관·파기, 권리 대응 원칙이 설계에 있는가 | `dataLifecyclePolicy`에 무저장 MVP, 짧은 TTL, 비식별 로그, 삭제/권리 대응을 포함했다. |

## 구현 반영

| 항목 | 변경 |
|---|---|
| API 요청 | 브라우저는 `hasPhoto`만 보내고 `photoName`은 보내지 않음 |
| 서버 normalize | 클라이언트가 `photoName`을 보내도 `input`에서 제외 |
| Analyzer | `dataLifecyclePolicy` 추가, `cycle-14`로 추적 |
| UI | `서버/AI 데이터 보관 설계` 섹션과 4개 보관 항목 표시 |
| 다운로드 리포트 | 텍스트 리포트에도 데이터 보관 설계 포함 |

## 테스트

추가한 테스트는 다음을 검증한다.

1. analyzer 결과가 `cycle-14` 데이터 생명주기 정책을 반환한다.
2. 정책 텍스트에 상세 위치나 사진 파일명 같은 원문 식별자가 들어가지 않는다.
3. 서버가 클라이언트 제공 `photoName`을 무시한다.
4. 브라우저 실제 API 요청에 선택한 사진 파일명이 포함되지 않는다.
5. 결과 화면에 서버 무저장, 브라우저 한정 사진 미리보기, 짧은 TTL 설계가 표시된다.

## 결정

Cycle 14 이후 MVP는 "피드백 최소화", "로컬 이력 최소화", "서버/AI 데이터 보관 최소화" 세 축을 갖는다. 다음 반복은 실제 사용자가 신고문을 수정하는 흐름과 수정 이력을 어떻게 다룰지 검토하는 방향이 적합하다.
