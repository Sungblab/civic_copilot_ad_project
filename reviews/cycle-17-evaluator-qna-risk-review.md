# Cycle 17 - Evaluator Q&A and Risk Defense Review

## 목적

발표와 보고서가 평가 기준에 맞춰 정리되었는지뿐 아니라, 질문이 들어왔을 때 설계 논리가 흔들리지 않는지 점검한다. 이번 반복은 기능 추가가 아니라 제출 직전 방어력 보강이다.

참조 리서치: `research/evaluator-qna-risk-defense-2026-05-25.md`

## 페르소나 리뷰

| 관점 | 날카로운 질문 | 반영 |
|---|---|---|
| 교수/평가자 | 기존 안전신문고와 무엇이 다른가 | "접수/처리"와 "접수 전 준비"를 분리한 답변을 예상 질문에 추가한다. |
| 동료 평가자 | 데모가 있으면 구현 프로젝트처럼 보이지 않는가 | MVP는 설계 검증 프로토타입이라는 답변을 발표 전략에 연결한다. |
| 행정 담당자 | 중복 신고와 업무 부담을 늘리는 것 아닌가 | 반복 민원 제도 근거를 바탕으로 차단이 아닌 보완 정보 안내라고 답한다. |
| 개인정보 검토자 | 사진·위치·신고문이 너무 민감하지 않은가 | 수정본 미저장, 지역 수준 이력, 서버 무저장, 짧은 TTL 설계를 Q&A에 묶는다. |
| 구현 검토자 | 실제 연동이 없으면 쓸모가 약하지 않은가 | 복사/외부 이동만으로도 신고 준비 부담을 줄이고, 공식 API 연동은 협약 후 확장이라고 설명한다. |
| 취약 사용자 관점 | 복잡한 결과 화면을 이해할 수 있는가 | 쉬운 3단계 안내와 120 외국어 상담을 설계 방어 포인트로 둔다. |

## 결정

질문 대응의 중심은 "기존 플랫폼을 대체하지 않는다"이다. 자동 제출, 공식 처리결과 관리, 민원 책임 판정으로 확장하면 과제 범위와 책임 경계가 흐려진다. Civic Copilot은 공식 접수 전 사용자가 더 정확하게 준비하도록 돕는 보조 시스템으로 유지한다.
