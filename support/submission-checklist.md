## 제출 전 확인

- [ ] AD 평가 기준인 문제 정의, 조사, 설계 논리, 발표 전달력이 각각 드러나는가?
- [ ] MVP가 구현 과시가 아니라 설계 검증 프로토타입으로 설명되는가?
- [ ] 첫 30초 안에 국민대/대학가 생활민원 상황이 공감되게 제시되는가?
- [ ] "기존 신고 플랫폼은 이미 있다"는 조사 결론이 들어가는가?
- [ ] 차별점이 "접수 전 검증·작성·라우팅"으로 명확한가?
- [ ] AI/SW 요소기술이 구체적으로 설명되는가? VLM, LLM, RAG, 규칙 DB, 채널 라우터.
- [ ] 불법주정차처럼 규칙이 명확한 유형에서 규칙 DB 필요성이 설명되는가?
- [ ] 서울 생활불편, 전국 안전신고, 긴급 신고의 채널 라우팅 차이가 설명되는가?
- [ ] 위치가 없을 때 지도 위치 지정, 주변 기준점, 사진 배경 보완이 필요하다고 설명되는가?
- [ ] 사진이 없을 때 현장 사진, 전체 배경 사진, 근접 사진 보완이 필요하다고 설명되는가?
- [ ] 얼굴, 차량번호, 상세 주소를 구분한 개인정보/마스킹 설계가 포함되는가?
- [ ] 중복 신고를 차단이 아니라 유사 신고 확인과 보완 정보 안내로 설계했는가?
- [ ] 공식 제출은 자동화하지 않고, 신고문 복사와 공식 채널 직접 제출로 경계를 명확히 했는가?
- [ ] AI 신고문 초안은 사용자가 사실/과장/개인정보를 검토하고 수정하는 흐름으로 설명되는가?
- [ ] AI 추천의 근거, 불확실성, 참고용 고지, 사용자 최종 확인 경계가 설명되는가?
- [ ] 디지털 취약 사용자와 외국인 주민을 위한 쉬운 3단계 안내와 120 외국어 상담 근거가 설명되는가?
- [ ] 피드백 루프가 선택형 비식별 신호이며 위치/신고문 원문을 저장하지 않는다고 설명되는가?
- [ ] 최근 분석 이력도 상세 위치/신고문 원문을 저장하지 않고 로컬 삭제가 가능하다고 설명되는가?
- [ ] 서버/API/AI 로그도 사진 파일명, 원본 사진, 상세 위치, 신고문 원문을 장기 저장하지 않는다고 설명되는가?
- [ ] 사용자가 수정한 신고문 원문은 복사/다운로드에만 쓰고 서버나 최근 이력에 저장하지 않는다고 설명되는가?
- [ ] 긴급 신고, 자동 제출 금지 같은 안전장치가 포함되는가?
- [ ] MVP 데모가 전체 설계의 핵심 흐름을 검증하는 프로토타입으로 설명되는가?
- [ ] 발표에서 말할 내용과 화면으로만 보여줄 백업 내용을 분리했는가?
- [ ] 데모 설명은 증거, 채널, 신고문, 안전장치 4개 핵심으로 압축되었는가?
- [ ] 발표 시간이 7분 이내인가?
- [ ] 리허설 기준 6분 40초~6분 55초 안에 끝나는가?
- [ ] 발표 본편에서 모든 데모 기능을 설명하려 하지 않고 핵심 흐름만 설명하는가?
- [ ] `support/expected-questions.md` 기준으로 예상 질문 9개를 20초 답변으로 말할 수 있는가?
- [ ] 모든 Q&A 답변이 "공식 플랫폼 대체가 아니라 신고 전 보조"라는 핵심으로 돌아오는가?

## 평가 기준 매핑

| 기준 | 확인 항목 |
|---|---|
| 문제 정의와 해결 논리 | 신고 플랫폼 부재가 아니라 신고 전 준비 실패로 문제를 좁혔는가 |
| 요소기술 조사 | VLM, LLM, RAG, 규칙 DB, 채널 라우터가 각각 어떤 역할인지 설명되는가 |
| 구현 가능성 | MVP와 실제 AI 연동 범위를 분리하고 공식 API 부재 시 복사/외부 이동 대안을 설명하는가 |
| 발표 전달력 | 핵심 문장, 시각 자료, 7분 시간 준수, 백업 설명 분리가 준비되었는가 |
